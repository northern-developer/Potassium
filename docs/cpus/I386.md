# i386 target notes

`machines/I386.json` is the smallest slice of 32-bit x86 that E4.T3's
ELFCLASS32 test program needs (`examples/I386.asm`, `tests/link/program.c`
as clang compiles it, linked statically): it checks ptasm's 32-bit ELF writer with **REL**
relocations against GNU's tools, and runs. It isn't an i386 assembler.

---

## 1. References

- Intel's *64 and IA-32 Architectures Software Developer's Manual*,
  Volume 2 (instruction encodings).
- The System V i386 psABI (relocations).

## 2. Machine

8 registers with AMD64's IDs (`R0` = eax, `R1` = ecx, `R2` = edx, `R3` =
ebx, `R4` = esp, `R5` = ebp, `R6` = esi, `R7` = edi), 32-bit addresses,
little-endian. PC-relative distances count from the next instruction
(`relOffset: "after"`).

ELF: `ELFCLASS32`, `e_machine` 3 (`EM_386`), **REL** relocations
(`relocationFormat: "rel"`: the addend is stored in the relocated field),
as GNU `as --32` writes them. Types: `"addr32": 1` (`R_386_32`),
`"pcrel32": 2` (`R_386_PC32`, what GAS uses for a non-PIC `call`).

## 3. Instructions

All 32-bit (no REX prefix; `machines/AMD64.json` is the 64-bit counterpart):

| ptasm | x86 | Encoding |
|---|---|---|
| `MOV Rn, imm` / `MOV Rn, label` | `mov r32, imm32` | `B8+r`, imm32 (a label: `R_386_32`) |
| `MOV Rd, Rs` | `mov r32, r32` | `89`, ModRM `11_sss_ddd` |
| `ADD`/`AND`/`SUB`/`CMP Rn, imm` | `add`/`and`/`sub`/`cmp r32, imm32` | `81`, ModRM `11_xxx_rrr` (xxx = 000, 100, 101, 111), imm32 |
| `PUSH Rn` / `POP Rn` | `push r32` / `pop r32` | `50+r` / `58+r` |
| `INC [label]` | `inc dword ptr [label]` | `FF 05`, absolute address (`R_386_32`) |
| `JNE label` | `jne rel8` / `jne rel32` | `75`, rel8 (a label in the section); `0F 85`, rel32 (otherwise) |
| `CALL label` | `call rel32` | `E8`, rel32 (another file: `R_386_PC32`, -4 in place) |
| `RET` | `ret` | `C3` |

GAS and clang write a small immediate as the 3-byte `83` form; ptasm always
writes the 6-byte `81` form.

## 4. Examples

- `examples/I386.asm`: `tests/link/program.c` as clang compiles it, with
  each hand edit marked `; ptasm:`.
- `examples/I386-negative.asm`: the jump the positive one doesn't make --
  a `JNE` to an `.EXTERN` label, the long form with an `R_386_PC32`
  relocation (REL: the -4 is stored in the field) -- and two errors that
  need `-w`.

## 5. Known gaps

- No RIP-relative addressing (i386 has none), so no PIE: position-
  independent i386 code reaches data through the GOT, which ptasm can't
  write (wish list, as for AMD64's `GOTPCREL`).
- ptasm doesn't relax branches: a `JNE` to a label more than 127 bytes
  away in its section is an error.
- The C side (`tests/link/main.c`) is built with `-mregparm=3`
  (arguments in eax, edx, ecx instead of on the stack), and supplies
  `write()` and `puts()` on `int 0x80`, so no 32-bit C library is needed.

## 6. How it's tested

`ctest`'s `link-i386` (`tests/cmake/link_check.cmake` mode `i386`, registered on x86-64 when
clang exists and `ld` has the `elf_i386` emulation): assemble the example
with `-f elf`, compile `tests/link/main.c` freestanding
(`PTASM_FREESTANDING`, `-mregparm=3`; no 32-bit C library needed), link
statically with `ld -m elf_i386`, run it, and compare its output with
what clang's own object for `tests/link/program.c` prints (and with the
AMD64 test's). Checked against `as --32` on the same program: identical
relocation offsets and types; GAS relocates against section symbols with
the offset in place where ptasm names the label.
